# Разработка Northfall

Карта проекта: как запустить, как устроено и что делать дальше.

## Что это

Northfall — текстовая браузерная RPG (тёмное фэнтези). Клиент — один большой HTML-файл,
сервер — Node.js на Fly.io, база — Firestore.

```
public/index.html        клиент (RU)  — весь код игры в одном файле
public/en/index.html     клиент (EN)  — генерируется из RU, руками не править
public/img/              графика (2.5 МБ)
server/index.js          HTTP-сервер: статика + функции Netlify + хаб
server/hub.js            сокет-хаб: раздаёт «горячие» коллекции Firestore игрокам
server/raid.js           рейды: общий босс живёт в памяти сервера
server/duel.js           лайв-арена: ходы и раунды считает сервер
server/saves.js          сохранения и экономика (рынок, письма, казна клана)
server/items.js          проверка вещей на честность
netlify/functions/       функции: аккаунт, золото, push, трекинг, Xsolla
netlify/lib/             общие библиотеки (firebase, промо, push, changelog)
i18n/                    сборка английской версии (acorn + словарь en.json)
tools/funnel.js          приём клиентских ошибок на сервер
tools/wstest.js          тест протокола сокета
tools/wsbench.js         замер трафика хаба
fly.toml                 конфигурация Fly.io
.github/workflows/       автодеплой на Fly.io при пуше в main
```

## Запуск локально

```bash
npm install
PORT=8080 CRON=off CHANGELOG=off node server/index.js
```

Открыть http://127.0.0.1:8080/ .

`CRON=off` и `CHANGELOG=off` отключают рассылку push-уведомлений и публикацию
списка изменений — локально они не нужны.

Без `FIREBASE_SERVICE_ACCOUNT` в окружении сервер работает, но не видит базу:
вход, сохранения и ленты отдают `503 not_configured`, статика и `/healthz` — в порядке.

### Проверки

```bash
node tools/wstest.js      # протокол сокета: 16 проверок, база замокана
node tools/wsbench.js 300 # сколько трафика уходит на игрока
node i18n/build_en.js     # пересобрать английскую версию клиента
```

## Правило обновлений

**Каждое обновление обязано попасть на форум в тему «Обновления игры» — и на русском, и на английском.** Игроки читают обновления там, а в чат приходит ссылка. Молчаливых релизов быть не должно.

Как это устроено:

1. `netlify/lib/changelog.json` — список записей `{v, t, te}`: `t` — русский текст, `te` — английский.
2. При выкладке срабатывает `netlify/functions/deploy-succeeded.js`: он публикует новые записи
   в тему форума `forum/tupdates` («Обновления игры») и `forum/tupdates_en` («Game updates
   (English)»), а также короткое сообщение в оба канала чата и в Discord.
   Что уже опубликовано — лежит в `priv/changelog-state`.
3. Ссылка на тему, которую даём в чате:
   - RU: https://playnorthfall.online/?go=forum&t=tupdates
   - EN: https://playnorthfall.online/en/?go=forum&t=tupdates_en

Чтобы выпустить обновление:

```bash
node tools/release.js 1.18.1 "Текст по-русски." "English text."
```

Помощник сам допишет запись в changelog, поднимет `GVER` в клиенте и пересоберёт
английскую версию. Потом коммит, PR, merge в `main` — и запись уедет на форум.

**Два правила, которые нельзя нарушать:**
- у каждой записи обязательно есть `te` — английский перевод; без него игроки
  в англоязычной версии не увидят обновления;
- версия в записи совпадает с `GVER` в клиенте.

Если правила Firestore меняются — их нужно **опубликовать в консоли Firebase**
(Firestore → Правила → Опубликовать, содержимое файла `firestore.rules`).
Файл в репозитории сам по себе ничего не меняет.

## Протокол сокета

Клиент подключается к `/ws` и общается JSON-сообщениями.

| Сообщение | Направление | Смысл |
|---|---|---|
| `hello` | клиент → сервер | вход: токен Firebase (`tok`) или гостевой id (`g`), версия протокола (`v`) |
| `me` | сервер → клиент | сервер узнал логин игрока |
| `sub` / `unsub` | клиент → сервер | подписаться на ленты (`players`, `clans`, `wars`, `world`, `chat`, `terr`, `raidq`) |
| `snap` | сервер → клиент | полный снимок ленты |
| `upd` | сервер → клиент | дельта: `u` — изменившиеся документы, `r` — удалённые id, `o` — порядок id |
| `onl` | сервер → клиент | список игроков онлайн |
| `rj` / `rd` / `rm` / `rh` | клиент → сервер | рейд: встать в комнату, урон, продвижение, удар по слуге |
| `rs` | сервер → клиент | состояние рейда |
| `dj` / `da` | клиент → сервер | дуэль: встать в комнату, ход |
| `ds` | сервер → клиент | состояние дуэли |

### Версии протокола

Версия объявляется в `hello` полем `v`.

- **v1** — старые клиенты: при каждом изменении сервер шлёт **полный снимок** ленты.
- **v2** — текущий: сервер шлёт **дельту** (только изменившиеся документы).

Версия выбирается в `hello`, так что старый клиент продолжает работать и после
обновления сервера. Клиент шлёт `v:2`; сервер для таких клиентов считает дельту,
для остальных — собирает снимок как раньше.

Зачем: лента `players` — до 300 документов. Полный снимок на каждое изменение при
50 игроках онлайн давал ~10 МБ/с. С дельтами — ~0.5 МБ/с (замер: `tools/wsbench.js`).

## Деплой

Пуш в `main` → `.github/workflows/fly.yml` → `flyctl deploy --remote-only`.
Ключи передаются из секретов GitHub в секреты Fly (`flyctl secrets set --stage`).

Секреты репозитория: `FLY_API_TOKEN`, `FIREBASE_SERVICE_ACCOUNT`, `XSOLLA_*`,
`RESEND_API_KEY`, `MAIL_FROM`, `DISCORD_WEBHOOK`.

Клиент и сервер едут в одном контейнере (`Dockerfile` копирует и `server`, и `public`),
поэтому протокол сервера и клиента обновляются атомарно.

Проверка после выкладки: `curl https://playnorthfall.online/healthz`,
`curl https://playnorthfall.online/hubz`.

## Роадмап

### Сделано

- **Дельта-протокол хаба** — трафик на игрока упал в ~20 раз (см. выше).
- **Тесты протокола** — `tools/wstest.js`, в проекте не было ни одного теста.
- **Замер трафика** — `tools/wsbench.js`.
- **Сервер не падает из-за одной комнаты** — тик рейдов обёрнут в try/catch,
  битый документ рейда больше не роняет процесс.
- **Утечка памяти в сохранениях** — карты `last` и `recent` чистятся по таймеру.
- **Порядок инициализации** — `fbAdmin` объявлен до использования (иначе был риск
  `ReferenceError` при изменении порядка строк).
- **Ограничение частоты запросов** (`server/ratelimit.js`) — `/api/save` и `/api/op`
  режутся по uid после проверки токена; трафик без токена — по IP. Каждое
  сохранение — транзакция Firestore, это основная статья расходов на базу.
  Лимиты щедрые: обычный игрок укладывается в 12–20 сохранений в минуту.
- **Тесты игровой логики** — `tools/gametest.js`, 22 проверки: раунд дуэли
  (урон, щит, оглушение, зелье, перезарядки, классы, ничья, лимит раундов)
  и сам ограничитель частоты.
- **`npm test`** — прогоняет оба набора тестов, `npm run bench`, `npm run build:en`.
- **Отчёт по безопасности** — `SECURITY.md`: где клиент может обойти серверную
  проверку экономики и в каком порядке это закрывать.

### Важно (обсудить)

1. **Экономику можно обойти напрямую.** `firestore.rules` разрешают вошедшему
   игроку писать `market`, `world`, `raids`, `wars`, `terr` и `saves` — то есть
   серверную проверку можно не проходить вовсе. Подробный разбор и план правки
   правил — в `SECURITY.md`. Это самое важное из «Важно».
2. **Единственная машина.** `fly.toml`: `shared-cpu-1x`, 256 МБ, `min_machines_running = 1`,
   `auto_stop_machines = off`. Сервер не масштабируется горизонтально: все подписки
   Firestore живут в одном процессе. До тысячи игроков онлайн — нормально,
   дальше нужен либо второй инстанс с разделением по лентам, либо переход на
   Cloud Run / несколько воркеров.
3. **`/hubz` открыт.** Отдаёт состояние рейдов, дуэлей и число клиентов без
   авторизации. Для наблюдаемости полезно, для закрытого контура — стоит закрыть.
5. **Клиент — монолит 600 КБ.** Правки в `public/index.html` рискованны: нет
   модулей, нет сборки, нет типизации. Первый шаг — вынести логику в ES-модули
   (`public/js/*.js`) с точками входа, чтобы изменения перестали быть «правкой монолита».
6. **Нет `package-lock.json` в репозитории.** Сборки на Fly не воспроизводимы:
   `npm install` подтягивает произвольные версии. Файл lock-файл стоит закоммитить.
7. **Стоимость Firestore.** Хаб слушает 7 коллекций; каждое изменение документа —
   чтение. При 50 активных игроках лента `players` может съедать дневной лимит
   Spark (50 000 чтений/сутки). Стоит смотреть в «Счётчики» Firebase Console.
8. **Тесты на дуэли есть, на рейды — нет.** Раунд дуэли (`dRound` в `server/duel.js`)
   покрыт. Волны рейда (`server/raid.js`) — тоже чистые функции, их стоит покрыть.

### Идеи для геймплея

- **Клановые войны**: `wars` — коллекция уже есть и раздаётся в ленту, но механики нет.
- **Территории (`terr`)**: данные есть, захвата — нет.
- **Рейды на 4+ человека**: волны общие (`RWV`), но потолок в 3 волны и нет
  сложности по размеру группы.
- **Арена с рейтингами**: дуэли считаются сервером, но нет ни рейтинга, ни
  сезонов, ни истории.
