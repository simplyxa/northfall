# Безопасность экономики: что можно обойти прямо сейчас

Документ описывает **проверенные** на 2026-11-07 места, где клиент может писать
в Firestore напрямую и тем самым обходить серверную проверку. Каждое место
подтверждено чтением кода (`server/`, `netlify/functions/`, `public/index.html`,
`firestore.rules`) — не догадками.

## Главное

Серверная логика в `server/saves.js` и `netlify/functions/gold.js` сделана
аккуратно: «копилка серебра» ограничивает доход честным потолком, кошелёк
золота (`wallet`) закрыт на запись для клиента, покупки считаются в транзакции.

Но **правила базы разрешают клиенту писать почти во все коллекции**, где лежит
экономика. Правило `allow write: if signed()` означает «любой вошедший игрок
пишет любой документ». Проверки на сервере при этом можно не проходить вовсе —
достаточно писать в базу из консоли браузера.

| Коллекция | Что может сделать игрок | Правило сейчас |
|---|---|---|
| `saves/{uid}` | накрутить серебро: +100 000 за запрос, повторять бесконечно | `me(id) && saneSave()` |
| `market/{id}` | поменять цену любого лота на 1 золото и купить | `signed()` |
| `world/{id}` | написать `killed: true` и `dmg: {uid: 999}` → золото за мирового босса | `signed()` |
| `raids/{rid}` | написать `st: 'win'` и свой `mem` → золото за рейд | `signed()` |
| `clans/{clan}/dep/*` | подделать записи казны клана | `signed()` |
| `wars/{id}` | подделать любую войну | `signed()` |
| `terr/{id}` | подделать территории | `signed()` |
| `players/{uid}` | вписать себе любой `rating` и `srat` (таблицы, арена) | `me(id)` |

### Цепочка «рынок → дешёвая покупка» — самая дорогая

1. Игрок пишет `market/{id}.price = 1` (правило `signed()` это разрешает).
2. Покупает лот через `goldApi({a:'market', id})`.
3. `netlify/functions/gold.js:113` берёт цену **из документа**: `const price = Math.floor(m.price || 0)`.
4. Покупка проходит за 1 золото вместо настоящей цены.

То же с рейдом: `gold.js:130` читает `R.st` и `R.mem` из документа рейда —
достаточно написать свой документ `raids/{свой_id}` с `st:'win'` и тремя
не-ботовыми участниками, и награда капает.

### Что уже защищено хорошо

- `wallet`, `priv`, `push` — `allow write: if false`. Платное золото лежит там.
- `payments` — только чтение админом.
- `dm/{pid}/m/{mid}` — забрать письмо может только получатель, и только один раз.
- `friends` — пишут только двое участников.
- `raids/{rid}/a/{uid}` — ход в дуэли пишет только сам игрок (это нужно оставить).

### Дыра в бейджеке серебра

Клиент шлёт сохранение раз в 5 секунд (автосейв при изменении энергии/здоровья),
и каждое сохранение — транзакция Firestore. Это основная статья расходов на базу.
Лимит частоты (`server/ratelimit.js`, добавлен вместе с этим отчётом) режет
всплески, но честному игроку хватает 12–20 сохранений в минуту.

## Что предлагаю сделать

### Шаг 1. Правила базы (нужно опубликовать вручную в консоли Firebase)

`firestore.rules` меняется вручную: *Firestore → Правила → Опубликовать*.
Файл в репозитории — только копия.

```js
// Рынок: выставление, покупка и снятие — только сервер.
match /market/{id} {
  allow read: if signed();
  allow write: if false;
}

// Мировой босс и территории: состояние ведёт сервер.
match /world/{id} { allow read: if signed(); allow write: if false; }
match /terr/{id}  { allow read: if signed(); allow write: if false; }

// Войны: объявляет сервер.
match /wars/{id}  { allow read: if signed(); allow write: if false; }

// Рейд: документ рейда — сервер; ход в дуэли остаётся за игроком.
match /raids/{rid} {
  allow read: if signed();
  allow write: if false;
  match /a/{uid} {
    allow read: if signed();
    allow write: if signed() && lg() == uid;
  }
}

// Кланы: участники и состав пишутся клиентом, казна — только сервер.
match /clans/{clan} {
  allow read: if signed();
  allow create: if signed();
  allow update: if signed() && request.resource.data.diff(resource.data).affectedKeys()
    .hasOnly(['inv','kicked','req','off','closed','acc','wq','b']);
  match /{sub}/{doc} {
    allow read: if signed();
    allow write: if signed() && sub != 'dep';   // казна — сервер
  }
}

// Сохранение героя: пишет только сервер.
match /saves/{id} {
  allow read: if me(id) || admin();
  allow delete: if admin() || me(id);
  allow create, update: if false;
}
```

### Шаг 2. Клиент: убрать запасной путь записи напрямую

`public/index.html:456` — `direct()` пишет `saves/{uid}` прямо из браузера.
Он включается сам, когда сервер вернул 5xx или 404. Пока такое правило
`allow create, update` разрешает клиенту писать в `saves`, **серверная защита
необязательна**: при любой ошибке сервера клиент сам её обходит.

После шага 1 `direct()` должен перестать писать и показывать игроку понятное
сообщение («сервер недоступен, прогресс не сохранён»), а не молча падать.

### Шаг 3. Публичная карточка игрока

`players/{uid}` клиент пишет сам (`public/index.html:454`), и туда попадают
`rating`, `srat`, `win`, `lose`. Их нельзя отдавать клиенту — иначе таблица
и арена редактируются из консоли. Вариант: сервер пересчитывает рейтинг и
записывает карточку сам, клиент — только `name`, `cls`, `av`, `eq`.

### Шаг 4. Куда уходят деньги

`wallet` закрыт правилами, но `netlify/functions/gold.js` переносит `au` из
сохранения в кошелёк при первом обращении (`ensure()`), ограничивая 1000
(`START_CAP`) и только для аккаунтов, созданных до 30.10.2026. После шага 1
сохранение пишет сервер, поэтому и перенос будет из серверного значения —
это стоит учесть при переводе.

## Порядок работ

1. Сначала клиент: убрать `direct()` и перевести `players` на сервер.
2. Потом правила: опубликовать новый `firestore.rules`.
3. Откат: если что-то отвалится, вернуть прежние правила одной публикацией —
   данные при этом не пострадают, меняются только права.

Так порядок безопасный: между шагом 1 и шагом 2 серверная защита ещё работает
как раньше, а после шага 2 её уже нельзя обойти.
